DJ Profile — Tier 1 native, Tier 2 deep-link

The v1 profile is internal-only: signed-in DJs see each other's pages, alumni stay on the roster forever (radio history is the point). Public publication is held until C4 ships handle reservation and the deep-link story matures.

● Tier 1 · native edit ● Tier 2 · deep-link

Tier 1 is the small-on-the-go field set: handle, show name, show day/time, pronouns. These map directly to the existing auth_user schema and are safe to edit from an iPhone form. Tier 2 is long-form content — bio, social links, custom avatars — that wants real composition affordances. It deep-links to dj.wxyc.org until v2 brings it in-app alongside C4.

Alumni get a muted treatment and a "last on-air" pill but are never archived or removed — same record, same handle, is_alum=true.

Try it

  • Tap Edit (top-right) to open the Tier 1 sheet
  • Switch tabs above to preview MD / Alumni / teammate states
  • Tap any Tier 2 row (bio / social / avatar) → toast confirms it would deep-link out
  • In edit mode, the pronoun chips populate the field; the day picker is a tappable single-select

BS contract

# Read GET /me/profile # own — full record GET /djs/{id}/profile # teammate or alum # Tier 1 write (whitelist) PATCH /me/profile { handle?, show_name?, show_day?, show_time?, pronouns? } # Tier 2 fields exist on auth_user # but are NOT in the PATCH whitelist — # edited via dj.wxyc.org until C4 lands.

Notes

  • Alumni filter: is_alum=true (added to schema; never removes the row)
  • Public publication (C4) gates Tier 2 native editing — when handles are public, in-app composition can ship safely
  • Memo / direct-message rail (the "Send Memo to Sarah" button) is a separate Pick — wired here as a no-op deep-link
  • Handle constraint matches the auth service: 3–32 chars, [a-zA-Z0-9_]
