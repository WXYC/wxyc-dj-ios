Artist Deep Dive — five backends in one round trip

The phone screen looks unified, but five different systems contribute. LML supplies the bio + Discogs photo via the existing metadata proxy. BS owns the catalog rows (the WXYC library, plus per-DJ and station play tallies). The semantic-index service computes the neighbor list — embeddings over a corpus we don't have in BS yet. And the reviews table lives in BS as a sibling to plays.

iOS calls one composed endpoint (/graph/artists/{id}/deep-dive). BS does the fan-out concurrently and stitches the response. Doing this on the phone would mean five sequential HTTPS handshakes on LTE plus an OAuth dance for semantic-index — easily 3-4× the wall-clock latency before the first paint.

The deeper reason for the proxy is authentication: semantic-index uses a different auth model (service token, not DJ JWT). Exposing that surface to the phone would mean a second token lifecycle in the iOS keychain. BS already holds the service-side credentials; let it broker.

BS contract

GET /graph/artists/{artist_id}/deep-dive # one composed call · returns: { artist: { bio, photo, region, ... }, catalog: [{ release_id, title, year, cover_hash, ... }], plays: { station: { count, last_played_at }, you: { count, last_played_at, top_albums } }, similar: [{ artist_id, name, similarity }], reviews: [{ id, headline, author, rating, ... }] }

Server-side fan-out

  • LML /proxy/metadata/artist — bio + Discogs photo
  • BS /library/by-artist — catalog rows + cover hashes
  • BS /djs/{id}/plays?artist_id=... — counts + top albums by you
  • BS /plays/station-stats?artist_id=... — station-wide counts
  • semantic-index /artists/{id}/neighbors — top-k by cosine sim
  • BS /reviews?artist_id=... — review list with ratings

Coordination notes

Depends on C1 — extending AlbumSearchResult with artist_id so search rows become tappable into this view. Identifier translation happens in BS: iOS only knows BS artist_id; BS resolves to whatever opaque key semantic-index needs internally. The phone never sees a semantic-index ID.
