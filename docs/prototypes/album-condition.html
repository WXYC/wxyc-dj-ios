Album condition — state enum + audit log + MD gates

The legacy markedMissingAt / markedFoundAt two-timestamp model conflates two distinct concerns: which observer last touched the row, and what the album is doing right now. With more than one DJ in the bin, the last write wins and earlier context is lost. ADR 0004 replaces that with a four-state enum — in_library, missing, damaged, in_repair — and an append-only transition log. Every state change writes one audit row with actor, source state, target state, timestamp, and free-text note. Multi-observer history stops being lossy.

Why MD gates only on the non-missing transitions: missing is a reversible field observation any DJ can make and undo when they find the LP behind another bin. damaged and in_repair are operational states that drive workflow — pulling the sleeve, dispatching to the repair queue, returning to rotation — and need a Music Director's signoff to keep the staffing model legible. The picker greys out states the current role can't reach; the backend re-checks the JWT role on every PATCH.

Issue-row layering — multiple concurrent observations attached to one album — is explicitly out of v1. The current model treats condition as a single mutually-exclusive enum; if "missing AND damaged" turns out to matter, that's a follow-up RFC, not a v1 reshape.

Try it

  • Toggle Role DJ / MD at the top — the picker enables or disables the MD-gated states
  • Toggle the Current condition variant — the badge color, the picker's available next states, and the audit log's most recent entry all change
  • Tap Change condition to open the picker sheet — pick a state, optionally add a note, hit Save
  • Tap Audit log to expand the full transition history

BS contract

PATCH /library/{album_id}/condition { "to_state": "missing", "note": "not in bin during show" }

Replaces the old /missing + /found endpoints. Backend validates the source→target transition against the role gate; returns 403 if a DJ tries to set a non-missing state. Each accepted call inserts one row into condition_transitions.

GET /library/{album_id}/condition-transitions?limit=N

Paginated, newest first. Drives the audit log disclosure on this screen.

Notes

iOS reads JWTPayload.role to grey out picker rows; backend enforces. Issue-row layering (concurrent observations) is out of v1 — condition is one enum at a time. The initial (initial) → in_library row is system-inserted at catalog import; everything after is human.
