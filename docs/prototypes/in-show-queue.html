In-show companion mode — Queue read + targeted writes

iOS becomes a first-class in-show companion to dj-site, not a replacement. The Queue is the unplayed-yet tail of the current show's flowsheet — DJs can read it from anywhere, then send tracks from Mail Bin or Search, reorder, and remove entries.

Both surfaces operate on the same Queue resource — last write wins. The Mail Bin → Queue handoff mirrors dj-site's convertBinToQueue: the row is queued with empty track_title, and the DJ fills it in on-air.

iOS leapfrogs dj-site on one thing: native drag-and-drop reorder. dj-site's handleReorder is currently a no-op; we wire the same PATCH /flowsheet/play-order contract here and ship it first.

Try it

  • Toggle On-air / Off-air at the top — write affordances dim when off-air
  • When on-air, tap + to send tracks from Mail Bin (multi-select) or Search
  • Long-press a drag handle (≡) to enter reorder mode — neighbours shift and a save toast fires
  • Swipe a row left to reveal Delete (try the Wednesday row)
  • Tap a row's ⋯ for the overflow menu

BS contract

GET /flowsheet/on-air?dj_id=me # poll every 30s GET /flowsheet/latest # now-playing GET /flowsheet/playlist # queue tail POST /flowsheet # add (empty title = bin handoff) PATCH /flowsheet/play-order # reorder DELETE /flowsheet/{entry_id} # remove

Out of scope for v1

FCC-adjacent operations stay with dj-site: show start/end, talksets, breakpoints, and DJ join/leave. iOS reads them; it doesn't write them yet.

On-air status comes from /flowsheet/on-air?dj_id=me. The write gate is enforced server-side too — iOS just hides the affordance when it knows the DJ isn't on-air, to avoid a confusing 403.
